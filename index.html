              How it works

              1. The sender creates a transfer and gets a code and a QR code.
              2. Your temporary name travels with your code, so the other side sees who the transfer is from before they accept. It is not an account, it lives only on this device, and you can change it any time.
              3. Or send the invite link instead of the code. The link carries the same details, plus your name, so the other side sees who invited them. It opens as a link where this page is hosted or saved at the same address. Anywhere else, paste the link into the code box and it works the same. The sender gets an answer link back the same way. The link is shared under your temporary name, so what people see is your name, not the long code string. The raw link stays one tap away under Show link.
              4. The receiver enters the code, or scans the QR, and gets an answer code and QR back.
              5. The sender enters the answer code. The two devices connect directly.
              6. Both sides see the same verify code. Check it matches before accepting.
              7. The receiver reviews what is being sent, then accepts. Files stream direct, with progress and a hash check at the end.
              8. Before anything is sent, every file goes through the Privacy Engine on the sender's device. It inspects the file and removes supported metadata, like GPS location, camera details, dates, and tags, from a copy. The original file is never changed. Only the cleaned copy is sent, and both sides see a Privacy report saying what was removed.
              9. While you are connected, you can chat in the Transfer card, under the transfer. Chat travels encrypted on the same connection, it is never saved, and it is gone when the transfer ends.
              10. The sender can pause and resume a send while it is moving.
              11. When it finishes, or times out, the connection closes. Nothing waits anywhere. If the other side disconnects first, start again.
              12. Testing on one phone: this app can be both sides. Use Send to send and Receive to receive, and switch between the tabs to pass the codes back and forth.

              What it does not do

              • It does not store anything on a server. There is no inbox and no central file storage in this version.
              • It does not work while one side is offline. Both devices must be online during the transfer.
              • It does not show who is online. With no server, the only way to know the other side is there is to connect. A code made minutes ago means they were online recently. A live online list needs the signaling service, the next step.
              • It does not give you a short code. With no server, the code has to carry the whole connection offer, so it is long. QR makes it painless when you are together. A short code needs the signaling service, which is the next step.
              • It does not hide that a transfer happened from the network path. The content is encrypted, twice: once by the connection itself, once by the app with a key only the two devices share.
              • Scrubbing removes embedded metadata only. It cannot remove what is visible inside a file, like a face, a street sign, an address, or words in a photo or screenshot. It also does not hide your network address from the connection itself.
              • Some formats cannot be scrubbed yet, like PDF, DOCX, ZIP, and HEIC. Files in those formats are labeled Not scrubbed on both sides, never marked clean. Scrubbing covers JPEG, PNG, WebP, GIF, MP3, WAV, and MP4 / MOV.

              Limits

              • Codes expire 10 minutes after they are made.
              • Files: up to 5 per transfer, 10 MB each.
